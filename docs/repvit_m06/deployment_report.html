1. 可以直接采用的结论

  • RepViT 已完成部署兼容修复。14 个 RepDW、81 个 BN 融合；18 处 GELU 改为 tanh 近似并使用稳定表达；7 处 SE 显式展开 gate，解决跨 batch 广播错误。
  • 在相同 GPU 精度请求下，RepViT 耗时更高。允许低精度时，RepViT 为 V3M 的约 2.41 倍；禁止低精度时约 2.21 倍。参数量、MAC 倍率不能直接代替实际延时。
  • RepViT 有两档已通过本轮测试的配置。禁止低精度：13.60 ms，真实最大误差 0.002384；允许低精度：7.33 ms，误差 0.009936，接近本轮 0.01 门槛。
  • 12M 整图尚未做端到端实测。下文整图数字由分块次数乘以实测 batch16 延时得到，须另外加上取块、色彩转换、拼接及前后处理成本。
本版修正了精度判定口径：V3M 低精度结果正常、全部有限，3.04 ms 已纳入主对比。最大绝对差 0.016454 超过本轮开发参考线 0.01，但该参考线不是已确认的产品验收标准，不能据此认定现有部署不合格。数值误差也不等于画质下降百分比。

4. RepViT 部署需要改哪些

1

融合 RepConv 与 BN 等价融合

使用 eval 统计，将 RepDW 的 3×3、1×1、identity 分支及内外 BN 合为单个 DW 卷积，其他 Conv/BN 一并融合。本模型共 14 个 RepDW、81 个 BN；不跨激活强行合并卷积。训练权重保留，导出推理副本。

2

精确 GELU 改为 tanh 近似 模型近似

原 18 处 exact GELU 转成 FlexErf，当前生产 SDK 无 Flex，无法加载。导出为 tanh 近似后消除 Erf/Flex。该改动不是严格等价融合；真实 16 裁块的近似本身 max_abs 约 0.000687、mean_abs 约 0.0000147。

GELU(x) ≈ 0.5x · [1 + tanh(√(2/π) · (x + 0.044715x³))]
3

Tanh 使用稳定表达 等价表达，验证舍入

本 SDK 的 half shader 用 exp(2x) 计算 Tanh，x 超过约 5.545 后溢出，Inf/Inf 形成 NaN。已在独立扫描和原网中复现；采用下式消除该指数溢出路径，保留 tanh-GELU 的函数语义。

tanh(x) = 2 · sigmoid(2x) − 1
4

SE 显式展开 gate，避开跨 batch 广播 等价重排与复制

原 GPU 将所有图乘上 gate₀；首个 SE 的 MUL 误差 0.8217，与错误 gate₀ 公式却只差 4.2×10⁻⁶。保留 SE 网络与参数，把 gate 整数 nearest 复制到与 feature 相同形状再相乘，修复 7 处。

feature: [N,H,W,C] → [1,NH,W,C]
gate: [N,1,1,C] → [1,N,1,C] → nearest复制到 [1,NH,W,C]
同形逐元素相乘 → reshape回 [N,H,W,C]

此处只是 SE 内部张量重排；没有把 N 张图拆成 N 个卷积网络，也没有删 SE 或把 gate 固定为常量。

5

保持部署合同与既有运行路径

固定 FP32 NHWC I/O [16,128,128,6]，对应 16 个 RGB256 裁块；FP16 只描述权重存储。87 个卷积保持 native batch16，沿用原 Y4UV/UV 顺序及生产 native-batch Winograd guard。没有增加最终 PACK/readback 补丁，没有修改生产接口、SDK源码或重新训练。

生产接入需采用本轮修复图，并与实际 SDK/模型版本绑定 GPU 编译缓存；精度开关须按已验证的配置设置。

5. 修复后的验证结论

已完成

  • FP32 对照 GPU 真实 max_abs 约 1.13×10⁻⁶。
  • FP16 两种 GPU 精度下，真实16裁块均有限，max_abs < 0.01。
  • 零、全一、固定随机输入，两种 GPU 精度均通过合成门槛 0.05。
  • 高精度倒序和重复槽控制通过；相对正常 GPU 输出的直接差均为 0。
  • 583/583 原节点进入单个 GPU delegate，无 CPU 回退；原生卷积 batch 审计通过。

结论边界

  • 低精度真实误差 0.009936 接近门槛，结论限定于本轮冻结输入。
  • GELU 近似误差、FP16 存储误差、GPU 计算误差分别记录。
  • 583 个 delegate 成员包含 180 个常量 DEQUANTIZE，不等于 583 个 GPU kernel。
  • 数值测试没有代替视觉效果验收，也没有做 12M 全链路墙钟实测。
  • 未覆盖旧模型和原报告；修复版单独交付。

V3M 的精度情况如何理解

相对 V3M 自身 FP32 源模型，禁止低精度时 max_abs 为0.00912690，允许低精度时为0.01645367；两者输出均正常、有限。这与 RepViT 修复前的 gate 跨图错误和 NaN 是不同性质的问题。

0.01 是本轮用于发现差异的开发参考线，尚未绑定产品视觉验收。V3M 低精度超过该线，报告保留数值差异，但不写成“部署失败”或“不合格”。本轮 probe 的精度选项已记录；实际应用最终采用哪一选项，以应用接入配置为准，本文没有新增生产源码开关核验。
